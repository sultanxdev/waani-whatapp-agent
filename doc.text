# PRD — Dermatology WhatsApp AI Lead & Appointment System

**Product:** Dermatology WhatsApp AI Agent
**Version:** V1.0
**Product Type:** Custom software implementation for one clinic
**Commercial Model:** One-time project fee
**Deployment:** Production deployment included
**Code Ownership:** Complete source code handed over to client
**Target Customer:** Dermatology / Cosmetic Dermatology / Aesthetic Clinic

---

# 1. Product Overview

## 1.1 Product Vision

Build a production-ready WhatsApp-based AI assistant for a dermatology clinic that automatically handles customer enquiries, answers clinic-approved FAQs, captures leads, assists with appointment booking, provides appointment information, and escalates medical or complex questions to clinic staff.

The system is designed as a **custom implementation for one clinic**, not as a multi-tenant SaaS product.

The final delivery includes:

* Complete source code
* Frontend dashboard
* Backend API
* Database
* WhatsApp integration
* AI agent
* Appointment management
* Lead management
* Human handoff
* Clinic knowledge management
* Analytics
* Mobile-responsive interface
* Production deployment
* Environment/configuration documentation
* Client handover documentation

---

# 2. Core Business Problem

Dermatology clinics receive enquiries through WhatsApp from:

* Instagram
* Facebook
* Google Business
* Website
* Existing patients
* Referrals
* Direct WhatsApp messages

Typical enquiries include:

* Consultation fee
* Doctor availability
* Clinic timings
* Location
* Acne treatment
* Hair-loss consultation
* PRP
* Laser treatment
* Pigmentation
* Acne scars
* Chemical peels
* Cosmetic procedures
* Appointment booking
* Appointment rescheduling
* Appointment cancellation

The clinic currently relies heavily on receptionists or doctors to answer repetitive enquiries.

Problems:

* Delayed responses
* Missed leads
* Repetitive conversations
* Manual appointment handling
* Poor follow-up
* No central conversation history
* No lead tracking
* No enquiry analytics

The system solves the operational problem:

> **WhatsApp enquiry → qualified lead → appointment → human handoff**

It is not intended to replace the dermatologist.

# 3. Product Positioning

The product should be positioned as:

## WhatsApp Lead & Appointment Automation for Dermatology Clinics

Not:

* AI Dermatologist
* AI Doctor
* Skin Diagnosis Bot
* Medical Advice Bot
* ChatGPT on WhatsApp

The system is an **administrative, informational and lead-conversion assistant**.

Medical diagnosis, prescriptions and treatment decisions must remain with the doctor/qualified clinical team.

---

# 4. Product Goals

## Primary Goals

1. Respond to WhatsApp enquiries quickly.
2. Reduce repetitive work for reception staff.
3. Capture and organize enquiries.
4. Convert qualified enquiries into appointments.
5. Give staff a complete conversation view.
6. Provide real-time appointment visibility.
7. Automatically escalate medical/complex conversations.
8. Give the clinic a professional dashboard.
9. Deliver the complete application and deployment to the client.
10. Make the system maintainable by another developer after handover.

---

# 5. Non-Goals

V1 must NOT:

* Diagnose skin diseases.
* Analyze patient images for diagnosis.
* Prescribe medicines.
* Recommend prescription medicines.
* Recommend treatment plans independently.
* Pretend to be a doctor.
* Replace the dermatologist.
* Provide emergency medical diagnosis.
* Store unnecessary sensitive medical information.
* Become a general-purpose medical chatbot.

# 8. WhatsApp Requirements

The system must use the official WhatsApp Business Platform / Cloud API.

It must support:

* Incoming messages
* Outgoing messages
* Webhooks
* Message status
* Text messages
* Buttons
* Lists
* Template messages
* Conversation tracking
* Human handoff

WhatsApp's current Business Messaging Policy requires businesses to have the recipient's phone number and opt-in before messaging them, allows normal replies during the 24-hour customer-service window, requires approved templates outside that window, and requires an accessible escalation path when automation is used.

Therefore the system must not be designed around unrestricted outbound messaging.

---

# 9. WhatsApp Webhook

Endpoint:

```text
POST /api/webhooks/whatsapp
```

Responsibilities:

1. Receive WhatsApp event.
2. Verify webhook authenticity.
3. Parse event.
4. Identify clinic.
5. Identify customer.
6. Check message ID.
7. Prevent duplicate processing.
8. Persist message.
9. Queue processing.
10. Return a successful webhook response quickly.

# 16. Medical Safety Layer

The system must distinguish:

```text
BUSINESS QUESTION
MEDICAL QUESTION
EMERGENCY SIGNAL
UNKNOWN
```

## Business question

Example:

> Consultation kitne ka hai?

Answer using clinic information.

## Medical question

Example:

> Mere acne ke liye kaunsi cream use karu?

System should not prescribe or diagnose.

Instead:

```text
This question requires guidance from the dermatologist.
Would you like me to connect you with the clinic team?
```

## Emergency signal

The AI must not attempt medical triage beyond the clinic-approved escalation process.

It should immediately provide the configured emergency/support instruction and escalate where appropriate.

# 56. Data Protection

The application will potentially process personal data, so data minimization and access control must be built into the system.

India's DPDP Rules, 2025 were officially notified by MeitY with phased commencement dates. The official Gazette includes security-related and organizational requirements, so the production system should be designed with appropriate access control, security safeguards, logging, retention/deletion processes and privacy controls rather than treating privacy as a future feature.

The clinic should obtain appropriate legal advice for its own notices, consent language, retention obligations and healthcare-specific compliance.

# 83. Architecture Principle

The most important architectural rule:

## AI does not own the truth.

The database owns:

```text
prices
services
doctors
availability
appointments
lead status
clinic information
```

AI interprets conversation and decides which approved action/tool is appropriate.

Example:

```text
Patient:
PRP kitne ka hai?

AI:
get_service_information("PRP")

Backend:
₹5,000

AI:
PRP consultation/service ki current fee ₹5,000 hai.
```

This prevents hallucinated business information.
